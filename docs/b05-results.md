## What the new tests verify

- **Multi-skill deterministic builds** (`tests/multi-skill.test.mjs`): byte-equal outputs across separate source roots for both skills; staging equals publication; `build:check` detects edited generated files in either skill; both bundles validate against the strict manifest schema with consistent release/schema versions and `built_at >= sources_checked_at`.
- **Schema validation** (`tests/knowledge.test.mjs` additions): missing/unknown/multiple `generated_references` rejected; a release context built before source review rejected; the router catalogue entry and router-entry domains (D01, D12) checked against the canonical inventory.
- **Single-skill and full-suite installation** (`tests/installation.test.mjs`): the actual Skills CLI installs `--skill qie`, `--skill qie-networks` and `--skill '*'` in both copy and symlink modes into clean consumer fixtures; the source fixture is deleted before validation; every installed bundle passes hash/link validation offline and the network helper still runs from the installed location.
- **Missing topical skills** (`tests/multi-skill.test.mjs`): an installed router with no sibling skills validates offline, labels planned skills `planned — not packaged in this release`, and contains explicit install remediation (`skills add <qie-forge-source> --skill <skill-name>`) plus the instruction to never read a nonexistent path.
- **Broken local references**: authored broken/escaping links in the router entry fail the build; handwritten authoring files cannot overwrite generated `routing.md`/`qie-a-z.md`.
- **Routing contract** (`tests/routing.test.mjs`, `tests/fixtures/routing-fixtures.json`): 23 frozen intents including all five PRD §8.3 example intents and the UJ-06 staking case; per fixture: catalogue route consistency, mainnet/testnet scope containment, native-vs-EVM scope separation, forbidden-route absence (e.g. no EVM skill as the route for native intents), routing-table publication of accepted rows, and presence of required safety behaviors in the installed router entry (no invented addresses, no compatibility upgrades, no EVM substitution for native tasks, approval boundary before mainnet writes, no key handling, no silent network substitution). Two regression guards assert the router never restates the mainnet/testnet chain IDs and never links into sibling skill directories.

## Corrections discovered during implementation

1. The router initially listed `qie-defi` and `qie-security` as logical handoffs, but no canonical domain routes to them (D09 → `qie-ecosystem`, D12 → `qie`). The handoff list was trimmed to actual catalogue routes rather than shipping a handoff to a skill the routing table cannot justify.
2. The B04 release context carried `built_at` `00:04:06Z` while its packaged sources were reviewed at `00:08:45Z` — every manifest asserted a release cut before its own source reviews. Fixed in data (release `0.2.0-router.1`, `built_at` `2026-10-19T01:00:00Z`) and enforced by new validation so it cannot recur.
3. `validateBundle` resolved the knowledge digest through a hardcoded `data/network-claims.json` path; it now resolves through the manifest's `snapshot_path`, which the schema restricts to the two known artifact paths.

## Remaining unverified work and blockers

- Whether a coding agent actually selects the frozen routes under real prompts (FR-002's ≥90% accuracy and 100% high-risk targets) is **not** claimed. The fixtures verify the catalogue/router contract deterministically and freeze the input set for the later cross-host evaluation (B13). No agent host behavior was exercised here.
- Official `skills-ref` validation remains blocked (unavailable offline; PyPI unreachable), as does published Git source/ref installation, update and rollback. No public release is declared; maintainer identity, namespace and licensing remain unset (B01/G0).
- No live RPC, wallet, SDK, indexer, bridge, contract, address or finality behavior was tested. All capabilities remain UNKNOWN; the address collections remain empty.
- **Release blocker recorded:** contract-address identity validation — `eth_getCode`-style evidence cannot prove issuer identity; no ecosystem contract may be promoted to VERIFIED until issuer/ABI provenance, scoped chain observations, human source review and conflict handling exist (see [decisions.md](decisions.md)).
