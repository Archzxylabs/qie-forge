# Counter reference app

A guarded, read-only EIP-1193 reference for the canonical QIE Forge wallet-read controller. It shows the smallest complete browser flow: explicit connection, chain binding, a validated `eth_call`, safe rendering, and invalidation on wallet events.

## What is canonical here

- The **contract source and tests** stay in [`recipes/build-test/assets`](../../recipes/build-test/assets). There is no second Counter implementation.
- The **read controller** is imported from [`recipes/wallet-read/assets/wallet-read.ts`](../../recipes/wallet-read/assets/wallet-read.ts), not copied.
- The **chain IDs and claims** come from the packaged snapshot [`skills/qie-wallets/data/network-claims.json`](../../skills/qie-wallets/data/network-claims.json).
- [`src/generated/counter.ts`](src/generated/counter.ts) is generated by `npm run example:prepare` from the compiled Counter artifact. It is marked `GENERATED`; do not edit it by hand. `npm run example:prepare:check` fails if it is stale.

## Run it

From the repository root:

```sh
npm run example:prepare
npm run example:dev
```

Then open the printed local URL. To build the static site:

```sh
npm run example:build
npm run example:preview
```

## Mock mode

The default **Mock demonstration** is a deliberate adapter that answers only `eth_chainId`, `eth_requestAccounts` and `eth_call`. It uses a synthetic account and contract address, displays a prominent `SIMULATED DEMONSTRATION` banner, and labels the contract address as a simulated fixture that is not deployed. It involves no wallet, RPC endpoint, funds or QIE evidence. The mock never replaces a real provider after a failure.

## Injected-wallet mode

Select **Injected wallet (real provider)**, choose QIE testnet or mainnet, paste the deployed Counter contract address for that network, then click **Connect**. The app:

- does not request accounts on page load;
- checks the wallet chain before requesting accounts and again before each read;
- rejects a wrong chain and tells you which chain ID is required;
- invalidates account and value on `accountsChanged`, `chainChanged` and `disconnect`;
- discards late in-flight results after invalidation;
- clears a previously displayed value when a read fails or returns malformed data;
- reports a missing or malformed contract address as input feedback without calling `connect()` on an already-ready session, focuses and flags the address field, and does not offer session retry for that input error;
- disposes the current session and clears the displayed value when the target address changes, so the corrected address requires a deliberate Connect and Read;
- renders all wallet- and provider-derived values with `textContent`, never HTML;
- never signs or broadcasts a transaction.

Provider discovery follows the [QIE wallet guide](https://docs.qie.digital/qie-wallet-integration-guide-for-websites): a usable EIP-6963 announcement with `rdns: me.qiewallet` takes priority, followed by `window.qie`, then the legacy `window.ethereum` provider. The app listens for announcements throughout the page lifetime and requests re-announcement when the user clicks Connect. Discovery does not request accounts or connect automatically, and a new announcement does not replace an already bound session. Provider metadata is a discovery hint; it does not establish wallet authenticity or tested capabilities.

The supplied [QIE Wallet listing](https://chromewebstore.google.com/detail/oljchdcgmibnjbbopolafbjncfhdacjb) matches source S19's extension ID. Enable **Testnet** in QIE Wallet settings before selecting QIE testnet. Open the app through the local development server or HTTPS so the extension can inject its provider.

You can click Connect before entering a Counter address to select an account and display its public address. Enter a deployed Counter address before reading. Changing that address clears the session, so connect again deliberately after setting it. No contract is deployed by this example and no address is invented for real mode. If no usable injected provider is present, the error offers the QIE Wallet installation link; mock mode remains an explicit user choice.

## Browser checks

```sh
npx playwright install --with-deps --no-shell chromium
npm run test:browser
```

The 22 checks use deterministic provider fixtures plus a no-wallet mock test. They retain the original connection, chain, read, invalidation, recovery and mock-labelling coverage, and add six cases: QIE announcements alongside a competing legacy wallet; `window.qie` priority; discovery on Connect after a missed announcement; malformed/unrelated announcements and legacy fallback; the supplied installation link when providers are missing; and QIE-style site disconnection through `accountsChanged([])`. They do **not** prove compatibility with an installed extension or a real wallet/version/network combination.

## Type checking

```sh
npm run typecheck
```

The root `tsconfig.json` covers the canonical controller, this example and the browser tests in strict mode. CSS side-effect imports are typed through Vite's client types, and the controller's JavaScript boundary is documented inline rather than replaced with a parallel TypeScript copy.
